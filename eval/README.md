# Данные для оценки качества

## `golden_set.yaml` — эталонный набор вопросов

52 вопроса в пяти группах. Метрики считаются по каждой группе отдельно:
усреднение по всему набору скрывает именно то, что интереснее всего.

| Группа | Что проверяет |
|---|---|
| `direct` | прямой вопрос терминами документации — базовый уровень |
| `natural` | «как спросил бы живой человек», своими словами |
| `similar` | различение похожих страниц справочника (`filter` против `map`) |
| `trap` | ответа в корпусе нет — правильно признаться в незнании |
| `cross` | ответ требует нескольких документов |

**Как собран.** Вопросы написаны по тексту самих документов, а не по выдаче
поиска. Это принципиально: если формулировать вопросы, подглядывая в то, что
система находит, метрики покажут не качество системы, а качество подгонки
под неё.

**Ловушки обязаны доказывать своё право так называться.** У каждой указано
поле `absent_terms` — слова, отсутствие которых в индексе проверяет тест
(`pytest -m db tests/test_golden.py`). Проверка появилась не из педантизма:
первые версии ловушек про `z-index`, `<input>` и `canvas` оказались негодными —
ответ на них в корпусе был, система отвечала правильно, а эталон считал это
промахом. Ловушка, на которую есть ответ, — худший вид ошибки в измерении:
она занижает именно ту метрику честности, ради которой всё затевалось.

## `judge_labels.json` — разметка для проверки судьи

Обоснованность ответов оценивает языковая модель («судья»). Судья ошибается,
поэтому его согласие с независимой разметкой измеряется отдельно — это
поправочный коэффициент ко всем его оценкам.

> **Важная оговорка о честности.** Эта разметка сделана **ассистентом
> (Claude), а не человеком.** В плане проекта предполагалась ручная разметка;
> фактически ответы размечал тот же тип инструмента, что и судит, — пусть
> и другая модель, и с полным текстом фрагментов перед глазами.
>
> Это ослабляет проверку: две языковые модели могут ошибаться согласованно.
> Число «согласие судьи с разметкой» следует читать как «согласие двух
> моделей между собой», а не как «согласие с человеком». Чтобы проверка
> стала полноценной, эти 19 ответов должен перечитать человек — файл
> для этого готов, менять надо только значения.

Допустимые значения: `подтверждается`, `частично`, `не_подтверждается`.

Размечены 19 содержательных ответов. Отказы в разметку не входят: в них
нечего проверять на обоснованность — они ничего не утверждают о предмете.
